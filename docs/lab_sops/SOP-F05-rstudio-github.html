RStudio Projects and GitHub

Author
Affiliation

Marc Los Huertos & Isaac Medina

EA Program, Pomona College

Published

2026-05-14

1. Purpose

R, RStudio, and GitHub combine as a resource for data analysis, display, and collaboration. This SOP provides instructions to create RStudio projects, connect them to GitHub repositories, and manage collaborative workflows using version control.

We do not expect you to be an expert on R or RStudio. However, some experience with a computer language will be helpful.

2. Scope

  • Applies to: All EA Program researchers using R for data analysis and collaborative projects
  • Does not apply to: Local-only R scripts with no version control requirements; Python or other language workflows
  • Location: RStudio Server (Pomona College) or local installations

3. Acknowledgements

The following have made substantial contributions to this SOP: Aparna Chintapalli. As always, we acknowledge the students who have tried to follow these instructions and made suggestions for improvement. If you have suggestions or edits, please let the authors know.

4. Definitions

RStudio: The user interface for R. While R itself is a free programming environment with a robust range of statistical packages, RStudio provides tools to track and publish analysis in an efficient and transparent way.

Local Install vs. Server: R and RStudio can be installed on a local computer from the CRAN download mirror sites. We also have access to the RStudio Server installed on the Pomona College mainframe, accessible via a web browser.

GitHub: A web-based Git repository hosting service for collaborative code and document management.

Version Control: A method to track changes in software, especially in collaborative projects. RStudio projects and GitHub repositories can be shared among collaborators, with contributions tracked via version control tools.

5. Why R + RStudio + GitHub?

These tools together enable four key principles:

Collaboration: You can easily collaborate with others and track who contributed to various parts of the repository. When working in a team and updating text and code, version control ensures you can trace how things changed.

Transparency: Others can see how you analyzed data, providing clear access to your methods.

Reproducibility: When you conduct an analysis, you can reproduce the results, which validates your findings.

Accessibility: Accessible from any computer via the web server. Because we can rely on consistent behavior and web-based servers, operating systems and hardware rarely limit what you can do in R.

Note

Becoming experienced with these programs is like learning to walk. We need to approach this in discrete steps. Some people will experience weeks of mistakes before feeling confident; others will learn quickly. How fast you get comfortable depends on many factors but will be greatly improved by the time you invest.

6. Interferences

  • R is updated approximately every six months. Occasionally, new versions will no longer run older code, requiring maintenance of older versions. This almost never affects new users.
  • RStudio Server needs a functional network connection. If the network is down, the server is inaccessible.

7. Health and Safety

  • Risk of carpal tunnel syndrome from extended computer use. Maintain good posture and a well-designed workstation.
  • Frustration is common! After running into baffling errors, go for a run, get dinner, or take a nap. You’ll often find a workaround after taking a break.

8. Required Materials

  • Laptop or desktop computer
  • Access to Pomona College’s SSO (single sign-on) and server
  • GitHub account (free at github.com)
  • Patience

9. Estimated Time

Initial setup requires approximately 45 minutes.

10. Introducing RStudio

10.1 RStudio Server Login

The RStudio Server is hosted by Pomona College, so you need a Pomona College login. Non-Pomona students need a new login each semester, obtainable from the help desk at Cowart Information Technology Services.

Server addresses:

  • On Pomona’s network (or VPN): rstudio.campus.pomona.edu
  • Off campus / non-Pomona networks: rstudio.pomona.edu

From non-Pomona networks you may get a privacy error. If so, go to Advanced and accept the privacy settings to continue.

10.2 The Four RStudio Panels

Working with RStudio can be confusing at first. Here are the four default panels:

Upper Left – Text and Code Editor: This panel displays your text files (.Rnw, .Rmd, .R, .tex, .txt). If no file is open, this panel won’t appear and the console takes the entire left side. Close files you’re not actively editing to avoid confusion.

Lower Left – Console: The R console where you enter commands directly or submit them from the editor above. Errors are displayed in red here. If you compile a LaTeX file, the log appears here too.

Lower Right – Files/Plots/Packages/Help: Shows your workspace files, installed packages, plots, and help documentation. If a plot is too large for the window, resize the panel.

Upper Right – Environment/History/Git: The Environment tab shows objects R has access to. The History tab displays your command history. The Git tab manages files between GitHub and your local/server directory.

TipTip

To see all four panels, create a new text file: File > New File > R Sweave. Save it as “Test.Rnw” and all four panels will appear.

11. Setting Up Accounts and SSH Keys

11.1 Create a GitHub Account

  1. Go to github.com and create an account
  2. Use your Claremont email address – this helps later if you want free private repositories for students at education.github.com
  3. For our purposes you will not need a private repository initially

11.2 Configure RStudio for knitr

  1. In RStudio, navigate to Tools > Global Options > Sweave
  2. Change the “Weave Rnw files” option from Sweave to knitr
  3. Apply and close

11.3 Create an SSH Key in RStudio

  1. Open RStudio (server or local)
  2. Navigate to Tools > Global Options > Git/SVN
  3. Click “Create SSH Key”
  4. Select “RSA” under SSH Key Type
  5. Leave the passphrase blank for now (add one later for extra security on sensitive projects)
  6. Click “Create” – a pop-up image will appear (an encryption visualization; close it)
  7. Click “View public key” and copy the contents with Ctrl-C

11.4 Add the SSH Key to GitHub

  1. Go to your GitHub profile (upper right corner of any GitHub page)
  2. Select “Settings”
  3. In the left menu, select “SSH and GPG keys”
  4. Click “New SSH key”
  5. Type a name (e.g., “myRStudio SSH key”)
  6. Paste the RSA key from your clipboard into the key field
  7. Click the green “Add SSH key” button

GitHub and RStudio can now communicate.

12. Linking an RStudio Project to a GitHub Repository

12.1 Clone a Repository

We will use a practice repository called beginnersluck (search GitHub for it under the username marclos).

  1. On the GitHub repository page, click the green “Code” button
  1. Select “Clone with SSH” – IMPORTANT: if the header says “Clone with HTTPS,” click the small “Use SSH” link to toggle. If you skip this step, the project is very hard to fix afterward.
  1. Copy the SSH URL to your clipboard

12.2 Create an RStudio Project from the Clone

  1. In RStudio, go to File > New Project
  2. Select “Version Control”
  1. Select “Git”
  1. Paste the SSH URL into the “Repository URL” field (Ctrl-V). The project directory name should auto-fill.
  2. Click “Create Project”
  1. If prompted about establishing authenticity, type yes and hit OK
  1. You should now see the repository files in RStudio. If nothing appears, check if your pop-up blocker is active and disable it for this site.

13. Daily Workflow: Pull, Edit, Commit, Push

13.1 Best Practices

Every time you sit down to work:

  1. Pull first (blue downward arrow in the Git tab) to get the latest changes
  2. Edit your files
  3. Commit your changes (check the staged boxes, write a commit message)
  4. Push your changes (green upward arrow) to share with collaborators

13.2 Pull Results

When you pull, you’ll get one of three results:

“Already up-to-date.” Your files have not been updated on GitHub since your last pull. If you expect changes from a collaborator, they may have forgotten to push.

Successful update. You’ll see a summary of files changed, insertions, and deletions.

Unsuccessful pull. You have local changes that conflict with remote changes. See Troubleshooting (Section 15).

13.3 Committing Changes

  1. In the Git tab (upper right), check the boxes next to the files you want to commit
  1. Click “Commit”
  2. Write a meaningful commit message describing your changes
  3. Click “Commit”

13.4 Push Results

“Everything up-to-date.” Nothing new to push.

Successful push. You’ll see a message like e2efe6f..0b18250 master -> master.

Unsuccessful push. See Troubleshooting (Section 15).

14. Collaboration

14.1 Becoming a Collaborator

To contribute to someone else’s repository, they must add you as a collaborator. Send your GitHub username to the repository owner so they can add you via Settings > Collaborators in the repository.

14.2 Adding Collaborators to Your Repository

  1. Go to your repository on GitHub
  2. Click Settings in the toolbar
  3. Click “Collaborators”
  4. Add your collaborators’ GitHub usernames

15. Troubleshooting

15.1 Identity Error

If you receive an identity error, fix it using the Git shell. In the Git tab, click the gear icon and select “Shell…” Then type:

git config user.email "your.email@claremont.edu"
git config user.name "Your Name"

15.2 Merge Conflicts

Merge errors occur when you and a collaborator have both modified the same section of a file. To resolve:

  1. In the Git tab, look for files with a “U” (unmerged) status
  2. Open the conflicted file – you’ll see markers like <<<<<<< HEAD and >>>>>>> origin/main showing both versions
  3. Edit the file to keep the correct content and remove the conflict markers
  4. Save the file
  5. Check the file’s box in the Git tab
  6. Commit with a message like “Resolved merge conflict”
  7. Push

15.3 “fatal: Not possible to fast-forward, aborting.”

Run this in the Git shell:

git pull --rebase

15.4 Pull is Rejected (Unmerged Files)

If you see “Pull is not possible because you have unmerged files,” you must resolve the merge conflicts first (see 15.2), then add and commit the changes before pulling again.

15.5 Divergent Branches

If you see “You have divergent branches and need to specify how to reconcile them,” run one of the following in the Git shell:

git config pull.rebase false   # merge (recommended for beginners)

Then try pulling again.

15.6 Non-Fast-Forward Errors

If another person has pushed to the same branch, Git won’t be able to push your changes. Fix by fetching and merging:

git fetch origin
git merge origin main

Or simply use git pull to perform both commands at once.

15.7 Nuclear Option: Deleting a Project

If you are willing to sacrifice your local changes (or have emailed them to a collaborator):

  1. Delete all files in the project directory
  2. Clear workspace and console (don’t save)
  3. Go to Session > Terminate R
  4. Start a new project by cloning the repository again (Section 12)

16. Advanced Topics

16.1 Creating a New Repository on GitHub

  1. Click the green “New Repository” button on GitHub
  2. Enter a repository name (dashes will replace spaces automatically)
  3. Choose Public or Private (students can apply for free private repos at education.github.com)
  4. Check “Add a README file” – always recommended
  5. Add a .gitignore file for R (this tells Git to ignore temporary R files)
  6. Choose a license (GNU General Public License is a common choice)
  7. Click “Create repository”
  8. Clone the new repository into RStudio using the steps in Section 12

16.2 Installing R, RStudio, and GitHub Desktop Locally

New users should start with the server. When ready for local installation, install in this order:

  1. R: cran.r-project.org
  2. RStudio: posit.co/download/rstudio-desktop
  3. GitHub Desktop (optional): desktop.github.com

19. Training Record

Before using R/RStudio/GitHub independently for EA Program research, personnel must:

  1. Read this SOP in full
  2. Create a GitHub account and configure SSH keys
  3. Successfully clone, pull, edit, commit, and push to the beginnersluck practice repository
  4. Demonstrate the pull-edit-commit-push workflow under supervision
  5. Be signed off by the PI or project lead
